# Таблица предположений

| Утверждение | Статус и основание | Как проверить |
|---|---|---|
| Ручной подсчёт транспортных потоков занимает слишком много времени | **Подтверждено заказчиком.** На один перекрёсток подсчёт обычно занимает около 5–6 часов, иногда больше | Замерить реальное время обработки нескольких перекрёстков сотрудниками |
| Основная проблема — именно ручная обработка видео, а не процесс съёмки | **Подтверждено заказчиком.** Съёмка всё равно требует человека, а основную экономию ожидают получить на этапе подсчёта | Разложить текущий процесс по этапам и сравнить трудозатраты на съёмку и обработку |
| Системе нужно считать не только количество машин, но и направление их движения | **Подтверждено заказчиком.** Для транспортного моделирования важно понимать, куда едет транспорт: прямо, налево, направо, на разворот | Проверить результат модели на размеченном перекрёстке с известными потоками по направлениям |
| На первом этапе достаточно определять автомобиль и его направление | **Подтверждено заказчиком.** Детальную классификацию транспорта можно добавлять позже | Сделать MVP без детальной классификации и проверить, решает ли он основную задачу |
| В дальнейшем автомобили нужно разделять по типам | **Подтверждено заказчиком.** Легковые автомобили, грузовики, автобусы и другие виды транспорта учитываются по-разному | Получить от заказчика используемую классификацию и проверить распознавание каждого класса |
| Пешеходов тоже нужно учитывать | **Подтверждено заказчиком.** Их количество и направления используются при проектировании перекрёстков и настройке пешеходных фаз | Добавить подсчёт пешеходов и сравнить результат с ручной разметкой |
| Система должна работать с видео разного качества | **Подтверждено заказчиком.** Встречаются HD, 720p, 480p и видео, снятые на телефон | Прогнать один и тот же сценарий на видео разного разрешения и сравнить точность |
| Разные ракурсы камеры не должны ломать работу системы | **Подтверждено как требование.** Видео может сниматься городскими камерами или вручную с разных точек | Собрать видео одного перекрёстка с нескольких ракурсов и сравнить результаты |
| Помехи в кадре не должны сильно снижать точность | **Подтверждено как проблема существующих решений.** Заказчик сталкивался с ошибками из-за веток и других объектов в кадре | Сделать набор видео с частичным перекрытием кадра и сравнить ошибку с чистым видео |
| Если перекрыта слишком большая часть кадра, видео проще переснять | **Подтверждено заказчиком.** При перекрытии примерно более 30% такое видео обычно не используют | Проверить точность модели при разных уровнях перекрытия: 10%, 20%, 30% и выше |
| Существующие решения не дают заказчику нужной точности | **Подтверждено опытом заказчика.** Ранее использовался TrafficData, но результат не устроил по точности | Взять одинаковое видео и сравнить ручной подсчёт, существующее решение и нашу модель |
| Автоматизация позволит заметно сократить трудозатраты | **Гипотеза.** Это основная ожидаемая ценность проекта, но точная экономия пока не измерена | Сравнить время ручной обработки и время работы с готовой системой на одинаковых видео |
| Для MVP скорость обработки не является главным критерием | **Подтверждено заказчиком.** Даже если 15-минутное видео обрабатывается долго, но без участия человека и с правильным результатом, это уже полезно | Сделать рабочий прототип и отдельно измерить точность и время обработки |
| В дальнейшем обработка должна быть быстрее ручного подсчёта | **Логичное требование заказчика.** Финальная система должна давать экономию времени | Сравнить общее время обработки одного перекрёстка вручную и через систему |
| Основной критерий качества — соответствие автоматического подсчёта ручному эталону | **Подтверждено заказчиком.** Планируется использовать ранее обработанные видео как эталон | Взять размеченные видео и посчитать процент ошибки по каждому направлению |
| Заказчик сможет предоставить данные для тестирования | **Подтверждено.** Есть видео, которые ранее уже были посчитаны вручную | Получить несколько видео вместе с эталонными таблицами или картограммами |
| Результат работы системы можно выдавать в виде таблицы | **Подтверждено заказчиком.** Сейчас итоговые данные хранятся в Excel | Согласовать структуру таблицы и показать заказчику тестовый экспорт |
| Картограмма перекрёстка будет полезным форматом результата | **Подтверждено заказчиком.** Это привычный формат представления транспортных потоков | Сделать прототип картограммы и показать заказчику |
| Сложная интеграция с внутренними системами на первом этапе не нужна | **Подтверждено заказчиком.** Отдельной информационной системы для этой задачи сейчас нет | Уточнить минимальный сценарий: загрузка видео → обработка → скачивание результата |
| Система должна подходить не только для одного конкретного перекрёстка | **Требование / гипотеза реализации.** Заказчик хочет использовать решение на разных перекрёстках | Проверить модель на нескольких перекрёстках разной формы и сложности |
| Чем сложнее перекрёсток, тем выше ценность автоматизации | **Гипотеза на основе текущего процесса.** При большом количестве направлений ручной подсчёт занимает больше времени | Сравнить экономию времени на простом и сложном перекрёстке |
| Основной пользователь системы — специалист по транспортному планированию | **Следует из разговора.** Сейчас именно специалисты получают видео, считают потоки и используют результат в проектах | Провести отдельное интервью с сотрудниками, которые непосредственно выполняют подсчёт |
| Пользователи положительно воспримут автоматизацию | **Мнение заказчика.** Подсчёт считается монотонной работой, которой обычно занимаются начинающие специалисты | Поговорить напрямую с несколькими сотрудниками, которые сейчас считают потоки вручную |
| Полученные данные действительно используются при принятии инфраструктурных решений | **Подтверждено заказчиком.** Они нужны для моделирования, организации движения, настройки светофоров и проектирования | Проследить один реальный проект от подсчёта потока до принятого решения |
| Экономический смысл системы зависит от стоимости её эксплуатации | **Подтверждено заказчиком.** Если инфраструктура и вычисления будут дороже ручного труда, решение теряет смысл | После прототипа посчитать стоимость обработки одного часа видео и сравнить с ручной работой |
| Можно размещать на cloud сервисах| **Подтверждено заказчиком.** Входные не являются персональными, поэтому сервис может быть размещён на сторонних мощностях.| Отсмотреть данные, которые пришлёт заказчик, на предмет наличия персональных данных и потом принять решение по размещению|
