# ADR-0001: Компактный публичный API и Swagger

- **Статус:** принято
- **Дата:** 2026-10-17
- **Решение:** объединить мелкие служебные endpoint’ы в ресурсные маршруты и генерировать Swagger из кода FastAPI.

## Контекст

Первая версия API имела отдельные маршруты для файла видео, preview-кадра, остановки анализа, смены топологии, сводки, событий, картограммы и рамок детекции. Swagger получался длинным, а frontend делал три запроса для одного экрана результатов. Контракты в issues повторяли одни и те же модели и быстро расходились с кодом.

Функциональные требования при этом не требуют отдельного endpoint’а для каждой части экрана.

## Решение

Публичный API состоит из 10 путей под `/api` и сгруппирован в Swagger по пяти темам: система, видео, зоны, анализ и результаты.

1. `GET /api/videos/{video_id}/media` заменяет два маршрута. `kind=file` отдаёт видео, `kind=frame` — JPEG-кадр.
2. `PATCH /api/runs/{run_id}` объединяет команды `cancel` и `set_topology`.
3. `GET /api/runs/{run_id}/results` по умолчанию возвращает `summary`, `events` и `cartogram` одним ответом. Параметр `view` позволяет запросить один раздел или `detections` для текущего кадра.
4. Добавление и правка события используют один ресурс `/api/runs/{run_id}/events` с методами `POST` и `PATCH`.
5. Swagger UI генерируется FastAPI по адресу `/docs`, а машиночитаемая схема — `/openapi.json`. Названия, enum, ограничения и описания берутся из моделей и декораторов в `app/main.py`.
6. Два служебных маршрута для загрузки эталона и оценки ошибки сохранены, но скрыты из основного Swagger, так как не участвуют в базовом пользовательском сценарии.

## Альтернативы

- **Оставить все мелкие endpoint’ы.** Отклонено: Swagger и контракты остаются перегруженными.
- **Скрыть старые endpoint’ы из Swagger, не меняя frontend.** Отклонено: число запросов и дублирование остались бы в коде.
- **Сделать один универсальный endpoint.** Отклонено: он был бы сложее для тестирования и разделения ответственности.

## Последствия

### Положительные

- В Swagger остались только основные пользовательские сценарии.
- Экран результатов получает сводку, события и картограмму одним HTTP-запросом вместо трёх.
- Один контракт в коде служит источником для Swagger и issues.
- Автотест фиксирует лимит в 10 публичных API-путей.

### Отрицательные

- Параметр `view` меняет форму ответа `/results`, поэтому клиент должен учитывать выбранное представление.
- Старые URL основного API удалены, поэтому внешние клиенты должны перейти на новые маршруты.

## Проверка

- `/docs` возвращает Swagger UI.
- `/openapi.json` содержит 10 путей под `/api`.
- Frontend и автотесты используют только новый контракт.
