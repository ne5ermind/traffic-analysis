# ADR-0004: SQLite и файловое хранилище

- **Статус:** принято
- **Дата:** 2026-10-17
- **Модуль:** `app/storage.py`

## Контекст

Приложение работает локально, а видео, веса моделей и CV-артефакты неудобно хранить в реляционной БД.

## Решение

Метаданные и статусы хранить в SQLite с WAL. Большие файлы хранить в `data/`, а в БД записывать переносимые относительные пути. API и worker открывают свои соединения.

## Последствия

- Системе не нужен отдельный сервер БД.
- Проект можно переносить между Docker и локальным запуском.
- SQLite подходит для одного worker, но не для горизонтального масштабирования.
