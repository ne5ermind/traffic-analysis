# Нефункциональные требования InnovaTransport

## NF-01. Производительность

В быстром режиме сервис должен обработать 15-минутную видеозапись не дольше чем за 30 минут на целевой конфигурации Docker с четырьмя CPU-потоками. Результат подтверждается полным benchmark, а не экстраполяцией короткого фрагмента.

## NF-02. Контролируемое завершение при сбое

Если worker перестал отвечать, пользователь должен получить явное сообщение об ошибке не позднее чем через пять минут. Интерфейс не должен бесконечно показывать состояние «Идёт анализ».

## NF-03. Локальность и конфиденциальность данных

Загруженные видео, detections, события и отчёты должны обрабатываться и храниться локально. Во время рабочего сценария пользовательские данные не должны передаваться внешним сервисам.

## NF-04. Целостность данных

Система должна связывать результаты с конкретными видео, сценами и запусками. Изменения событий должны версионироваться, записываться в журнал ревизий и защищаться от перезаписи устаревшей версией.

## NF-05. Удобство использования

Основной сценарий «загрузка → анализ → проверка → экспорт» должен выполняться через русскоязычный интерфейс. Ошибки должны сообщать пользователю причину и возможное следующее действие.

## NF-06. Переносимость данных

Пути к видео, моделям и результатам должны сохраняться переносимо, чтобы один каталог данных можно было использовать при локальном запуске и в Docker без ручного исправления базы.

## NF-07. Совместимость среды

Проект должен запускаться через Docker Compose и без Docker на Python 3.11 или 3.12 при наличии системных зависимостей для ffmpeg и OpenCV.

## NF-08. Тестируемость и сопровождаемость

Каждый Pull Request должен проходить автоматические тесты API и бизнес-логики, компиляцию Python, синтаксическую проверку JavaScript и проверку Docker Compose.

## NF-09. Документированность API

Swagger UI должен быть доступен по `/docs`, OpenAPI JSON — по `/openapi.json`. Публичная схема должна содержать компактный набор из 10 согласованных API-путей.

## NF-10. Адаптивность интерфейса

Основные функции интерфейса должны оставаться доступными на desktop, mobile portrait и mobile landscape: элементы не перекрываются, подписи читаются, критичный контент не исчезает.

Момент, метод и критерий проверки каждого требования приведены в [`REQUIREMENTS.md`](./REQUIREMENTS.md).
