# Таблица предположений

| Утверждение | Статус и основание | Как проверить |
|---|---|---|
| Ручной подсчёт транспортных потоков занимает слишком много времени | **Подтверждено заказчиком.** На обработку одного перекрёстка обычно уходит около 5–6 часов, иногда больше | Замерить реальное время ручной обработки нескольких перекрёстков |
| Основная проблема находится на этапе обработки видео, а не его съёмки | **Подтверждено заказчиком.** Съёмку полностью убрать нельзя, но ручной подсчёт можно автоматизировать | Разложить текущий процесс по этапам и сравнить затраты времени |
| Автоматизация подсчёта позволит значительно снизить трудозатраты | **Гипотеза.** Это основная ожидаемая ценность продукта | Сравнить время ручного подсчёта и обработки тех же видео системой |
| Пользователю важно знать не только количество машин, но и направление их движения | **Подтверждено заказчиком.** Данные о направлениях используются в транспортном моделировании | Сравнить направления, найденные системой, с ручной картограммой |
| Для первой версии достаточно определять транспорт и его направление | **Подтверждено заказчиком.** Детальную классификацию можно развивать постепенно | Сделать MVP с определением объектов и направлений и показать заказчику |
| В дальнейшем транспорт необходимо разделять по типам | **Подтверждено заказчиком.** Разные типы транспорта учитываются по-разному | Получить от заказчика используемую классификацию транспорта и проверить модель |
| Основные классы — легковые, грузовые, автобусы, мотоциклы и велосипеды | **Рабочее предположение на основе задачи.** Точный набор классов ещё нужно согласовать | Получить от заказчика нормативы / классификацию, которую они используют |
| Пешеходов тоже необходимо считать | **Подтверждено заказчиком.** Их количество влияет, например, на пешеходные фазы светофора | Проверить подсчёт пешеходов на вручную размеченном видео |
| Для пешеходов достаточно количества и направления движения | **Подтверждено разговором.** Детальная классификация пешеходов не требуется | Согласовать структуру результата с заказчиком |
| Система должна работать с видео разного качества | **Подтверждено заказчиком.** Используются записи от HD до 480p и съёмка на телефон | Протестировать модель на видео разного разрешения |
| Система должна работать с разными ракурсами камер | **Подтверждено заказчиком.** Камера может находиться на разной высоте и под разным углом | Собрать несколько видео одного или разных узлов с отличающимися ракурсами |
| Частичные помехи не должны полностью ломать подсчёт | **Подтверждено как проблема существующих решений.** В кадре могут быть ветки и другие объекты | Проверить систему на видео с частичной окклюзией |
| При очень сильном перекрытии кадра видео проще переснять | **Подтверждено заказчиком.** Обсуждался ориентир примерно в 30% перекрытия кадра | Проверить качество работы при разных степенях перекрытия |
| Существующие решения не всегда дают нужную точность | **Подтверждено опытом заказчика.** Ранее тестировалось другое решение, которое не устроило по точности | Прогнать одно видео через существующее решение, нашу систему и ручной эталон |
| Готовой pretrained-модели может быть достаточно для первой версии продукта | **Гипотеза.** Собственную модель желательно не обучать, пока не доказана необходимость | Проверить YOLO/другую готовую модель на реальных видео заказчика |
| YOLO сможет достаточно хорошо определять основные классы транспорта | **Гипотеза.** Сейчас это базовый detector системы | Провести тест на размеченной выборке заказчика и посчитать precision/recall |
| Tracking позволит избежать повторного подсчёта одного автомобиля | **Техническая гипотеза.** Для этого используется ByteTrack или аналогичный tracker | Сравнить число уникальных треков с ручным подсчётом |
| Траектории объектов можно использовать для автоматического определения направлений | **Гипотеза.** В текущей концепции похожие траектории объединяются в потоки | Сравнить автоматически найденные движения с ручной картограммой |
| Большинство основных направлений можно определить автоматически | **Гипотеза.** На сложных узлах могут понадобиться ручные зоны | Проверить автоматическую кластеризацию на разных типах перекрёстков |
| Редкие движения могут не определяться автоматически | **Ожидаемое ограничение.** Например, редкий разворот может не сформировать отдельный кластер | Проверить на видео с редкими манёврами |
| Возможность вручную задать зоны въезда и выезда решит часть ошибок автоматического определения направлений | **Гипотеза реализации** | Дать специалисту настроить несколько перекрёстков и оценить удобство и точность |
| Тип перекрёстка можно автоматически определить по нескольким ключевым кадрам | **Гипотеза.** Для этого можно использовать локальную vision-language модель | Проверить VLM на наборе перекрёстков с известным типом |
| Для определения типа перекрёстка не нужно анализировать каждый кадр большой VLM-моделью | **Техническое предположение.** Геометрия перекрёстка обычно постоянна в течение записи | Сравнить результат по 5–10 ключевым кадрам с анализом большего количества кадров |
| VLM можно использовать как дополнительного проверяющего, а не как основной счётчик | **Гипотеза архитектуры.** Основные числа должны формироваться detector + tracker | Сравнить случаи, где VLM подтверждает или отмечает проблемы основного pipeline |
| Скорость обработки не является главным критерием первой версии | **Подтверждено заказчиком.** Даже долгая автоматическая обработка полезна, если не требует ручной работы и даёт правильный результат | Показать рабочий прототип и уточнить приемлемое время обработки |
| В дальнейшем система должна работать быстрее ручного подсчёта | **Логичное требование проекта** | Сравнить полное время обработки одного и того же видео человеком и системой |
| Главный критерий качества — совпадение с результатом ручного подсчёта | **Подтверждено заказчиком.** У заказчика есть ранее обработанные материалы | Сравнивать результаты системы с эталонными видео и таблицами |
| Заказчик сможет предоставить несколько эталонных видео | **Подтверждено заказчиком** | Запросить видео и соответствующие им результаты ручного подсчёта |
| Эталонные видео можно использовать для тестирования системы | **Подтверждено** | Создать тестовый набор и регулярно прогонять новые версии модели |
| Для оценки результата нужно считать ошибку отдельно по направлениям | **Рабочее предположение** | Согласовать с заказчиком формат отчёта по ошибкам |
| Допустимый процент ошибки пока не определён | **Не подтверждено / требуется уточнение** | Спросить заказчика, какую ошибку он считает приемлемой |
| Excel подходит как основной формат выгрузки | **Подтверждено заказчиком.** Сейчас результаты уже используются в табличном виде | Сделать тестовый XLSX и показать заказчику |
| Картограмма перекрёстка является полезным форматом результата | **Подтверждено заказчиком** | Создать прототип картограммы и получить обратную связь |
| CSV и JSON будут полезны для дальнейшей интеграции | **Гипотеза команды** | Уточнить, планируется ли использование результатов другими системами |
| Сложная интеграция с существующей системой на первом этапе не нужна | **Подтверждено заказчиком.** Специальной системы для этого процесса сейчас нет | Реализовать автономный сценарий загрузка → анализ → экспорт |
| Система должна работать на разных перекрёстках, а не только на одном | **Подтверждено как общее требование** | Протестировать на нескольких узлах разной геометрии |
| На сложных перекрёстках автоматизация даст больше пользы | **Гипотеза.** Сейчас сложность ручного подсчёта растёт вместе с числом направлений | Сравнить экономию времени на простом и сложном узле |
| Основные пользователи системы — специалисты по транспортному планированию | **Следует из интервью с заказчиком** | Провести интервью с непосредственными исполнителями |
| Сотрудники, которые сейчас считают видео вручную, положительно воспримут автоматизацию | **Мнение заказчика.** Работа монотонная и требует много времени | Провести несколько интервью непосредственно с исполнителями |
| Интерфейс должен быть простым и не требовать знаний в ML | **Гипотеза продукта** | Провести пользовательский тест со специалистами заказчика |
| Пользователю достаточно загрузить видео и получить результат без настройки модели | **Основная продуктовая гипотеза** | Дать специалисту пройти сценарий без помощи разработчика |
| Ручная настройка должна использоваться только в проблемных случаях | **Гипотеза продукта.** Приоритет — автоматический режим | Посчитать долю видео, где понадобилось ручное вмешательство |
| Стоимость автоматической обработки должна быть ниже или сопоставима с ручной работой | **Подтверждено логикой заказчика.** Слишком дорогая инфраструктура делает решение бессмысленным | Рассчитать стоимость обработки одного часа видео на CPU/GPU и сравнить с ручным трудом |
| Локальная обработка данных будет удобна заказчику | **Рабочее предположение.** Текущая архитектура позволяет хранить данные на своём сервере | Обсудить требования к размещению системы с заказчиком |
| Собственную модель нужно подключать только если готовые модели не обеспечат нужную точность | **Гипотеза команды** | Сначала провести benchmark готовых моделей на эталонных данных |
