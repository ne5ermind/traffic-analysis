# Проверка интеграции локальных Qwen — 24.09.2026

Выполнено на Mac пользователя, без облачной передачи видео.

- Установлены и доступны в Ollama `qwen3-vl:8b` и `qwen3.5:9b`.
- YOLO11s скачан из официального репозитория Ultralytics и выбран в `.env`.
- Обе модели дали настоящие структурированные ответы на ночное видео пользователя.
  Их предварительные оценки геометрии различались. Это не эталон правильной разметки.
- Обнаружена особенность Ollama: готовый JSON Qwen3-VL иногда находится в
  `message.thinking` при пустом `message.content`. Разбирается только полный
  JSON, прошедший ту же строгую схему; произвольный текст не используется.
- Финальный полный набор: 54 теста прошли (3 предупреждения зависимостей).
- Настоящими ffmpeg-файлами проверены MP4, MOV (вертикальный), M4V, MKV,
  AVI, WebM, MTS, M2TS и размеры от 160×120 до 1280×720.
- Ruff, TypeScript и production-сборка Vite проходят.
- Backend собран; Docker API, Redis, worker и frontend запущены.
  `/health` подтвердил связь контейнера с обеими локальными моделями.
- Через действующий HTTP API загружен короткий MOV 2072×1176.
  В браузере отредактирован центр схемы, сохранение подтверждено чтением API.
  Временный проект после проверки удалён.
- В браузере проверены SVG с тремя и четырьмя подходами, суммы и подписи.
  На проверенных страницах не обнаружено ошибок JavaScript.
- 375 px: проверен экран результатов без горизонтального переполнения.
  Попытка изменения ширины редактора не применилась; редактор проверен на
  фактических ширинах 968 и 1280 px, мобильную проверку редактора не заявляем.

### Полный прогон сохранённого проекта

- Проект: `08f1aa52-7337-4bab-a8ce-f89249249d16`.
- MOV/H.264, 2072×1176, длительность 128.515 с, около 24.98 FPS.
- Профиль accurate, YOLO11s, Docker CPU. Время полного задания 949.76 с.
- Прочитано 3211 кадров; контейнер сообщал оценку 3212. Такой допуск
  предусмотрен для метаданных контейнера/последнего кадра.
- 1702 сырых обнаружения, 13 треков, 7 подтверждённых треков транспорта,
  6 коротких исключены. Все 7 остались без надёжного направления.
- Qwen3-VL обработал 3 кадра и предложил T-схему. Qwen3.5 обработал
  4 кадра с данными детектора и вернул `review`, указав размытие, шум,
  блики и пропущенные объекты; `topology_consistent=false`.
- Семь треков — результат детектора, **не измеренное истинное число проездов**.
  Геометрия требует ручного уточнения. Самооценки Qwen не являются точностью.
- После прогона добавлена проверка невозможного расположения центра вне
  области подходов. Числа по спорной нейросетевой геометрии скрываются
  на картограмме; общий итог и исходные треки сохраняются.
- Новый строгий валидатор проверен регрессионными тестами; повторный полный
  16-минутный прогон после этой проверки не запускался. Первый настоящий
  прогон и его замечания сохранены в проекте, не заменены синтетическими данными.

После финального обновления `/health` подтвердил API, Redis, один worker и
обе Qwen. SVG, CSV, XLSX и JSON экспорты вернули HTTP 200; сохранённый
результат пережил пересоздание контейнеров. В спорной SVG-схеме нет
числовых стрелок, отдельно указаны 7 треков без направления.

Ни тесты с MockDetector, ни успешный вызов Qwen не доказывают точность подсчёта.
Для измерения ошибки нужен ручной эталон этого же видео.

Предупреждения тестов: два уведомления Starlette о будущей смене TestClient
и Torch TracerWarning для намеренно константного тестового выхода. Ошибок нет.

## Реальная модель и пользовательский сценарий

Использованы официальные веса YOLO11n из Ultralytics assets v8.3.0 и
публичный [OpenCV vtest.avi](https://github.com/opencv/opencv/blob/4.x/samples/data/vtest.avi).
SHA256 весов: `0ebbc80d4a7680d14987a577cd21342b65ecfd94632bd9a8da63ae6417644ee1`.

Из доступного начала исходника FFmpeg создал валидные MP4 на 6 и 15 секунд,
768 × 576, 10 FPS. Это уличная сцена с пешеходами и припаркованными машинами,
а не эталон движения транспорта на перекрёстке.

Через работающий интерфейс выполнены создание проекта, загрузка MP4,
запуск реальной очереди Redis/RQ, ожидание worker, открытие результатов,
создание линии, сохранение и пересчёт без detector. В браузере проверены
разметка bbox на кадре, переключатели слоёв и запуск воспроизведения.

Шестисекундный ролик: 270 detection, 11 треков, 8 подтверждённых объектов,
3 коротких трека исключены. Модель классифицировала 1 car, 1 truck и
6 pedestrian. Автоматических направлений недостаточно для кластера:
объекты остались unknown. После задания контрольной линии один пешеход
назначен направлению пересечения, общие количества сохранились.

Отдельный реальный pipeline на 15 секундах: 732 detection, 21 трек,
15 подтверждённых объектов, 6 коротких исключены; 1 car, 1 truck,
13 pedestrian. Найден один автоматический пешеходный поток из 3 треков,
надёжность 0.281 с флагом проверки; 12 объектов остались unknown.

Это **наблюдаемые результаты алгоритма, не ручной эталон и не доказательство
точности**. В частности, парковавшиеся автомобили попадают в unknown.

Выгрузки проверены через реальный HTTP API: XLSX открывается, содержит
Summary, Movements, Time intervals, Tracks, Metadata; JSON содержит
11 сохранённых треков; CSV и SVG доступны. HTTP Range вернул 206 и
ровно запрошенные 100 байт браузерного видео.

Интерфейс визуально проверен на 1440, 768 и 375 px. На узких экранах
страница не имеет горизонтального переполнения; широкие таблицы имеют
собственную прокрутку. Playwright-сценарии в `frontend/e2e` добавлены,
но отдельный Playwright runner в этом прогоне не запускался: браузерная
проверка выполнена через встроенный браузер Codex.
