# Стейкхолдеры проекта

## Кто участвует в проекте

| Стейкхолдер | Роль в проекте | Интерес / ожидание | Влияние | Что от него нужно |
|---|---|---|---|---|
| **Заказчик — ИнноваТранс** | Ставит задачу, принимает и проверяет результат | Получить инструмент, который автоматически считает транспортные потоки по видео и снижает ручные трудозатраты | Высокое | Требования, эталонные видео, результаты ручного подсчёта, обратная связь по прототипу |
| **Представитель заказчика / руководитель** | Основной контакт со стороны заказчика, принимает результат | Корректный подсчёт потоков, понятный формат результата, разумная стоимость эксплуатации | Высокое | Согласование требований, критериев проверки и формата результата |
| **Команда разработки / студенты проекта** | Разрабатывает и тестирует систему | Сделать рабочий MVP: распознавание транспорта, направлений движения и автоматический подсчёт | Высокое | Доступ к данным, регулярная связь с заказчиком, уточнение спорных требований |
| **Специалисты по транспортному планированию** | Используют результаты подсчёта в рабочих проектах | Быстро получать достоверные данные для моделирования и проектирования | Высокое | Проверка удобства результата и соответствия реальному рабочему процессу |
| **Сотрудники, которые сейчас считают потоки вручную** | Текущие исполнители процесса AS-IS | Сократить монотонную ручную работу и количество повторных пересчётов | Среднее | Интервью по текущему процессу, проверка удобства будущего решения |
| **Коллеги, которые занимаются подсчётом потоков в Сухуми** | Дополнительные эксперты по текущему процессу | Могут помочь разобрать реальный customer journey: съёмка, разметка направлений, подсчёт, перепроверка | Среднее | При необходимости — созвон или интервью для уточнения процесса |
| **Специалисты по математическому моделированию транспортных потоков** | Используют данные после подсчёта | Получать корректные интенсивности и направления движения для калибровки моделей | Среднее | Уточнение требуемого формата и детализации данных |
| **Проектировщики организации дорожного движения** | Используют результаты анализа для подготовки решений | Понимать фактическую загрузку перекрёстков и направления движения | Среднее | Проверка того, хватает ли выходных данных системы для дальнейшей работы |
| **Органы / специалисты, принимающие решения по транспортной инфраструктуре** | Косвенные пользователи результатов анализа | Использовать данные при изменении светофорных циклов, разметки, схем движения и реконструкции | Среднее | На этапе MVP прямое участие не требуется |
| **Университет / инфраструктура университета** | Возможная площадка для запуска и тестирования прототипа | Дать команде возможность развернуть тестовую версию решения | Низкое / среднее | При необходимости — вычислительные ресурсы для тестового развёртывания |

---

## Основные стейкхолдеры для MVP

На первом этапе критичны четыре стороны:

1. **Заказчик** — определяет, что считается приемлемым результатом.
2. **Команда разработки** — делает и тестирует решение.
3. **Специалисты по транспортному планированию** — понимают, какие данные реально нужны в работе.
4. **Сотрудники, выполняющие ручной подсчёт** — лучше всего знают текущий процесс и его проблемы.

## Матрица влияние / интерес

| Стейкхолдер | Интерес | Влияние | Как работать |
|---|---|---|---|
| Заказчик | Высокий | Высокое | Постоянно держать в курсе, регулярно показывать промежуточный результат |
| Команда разработки | Высокий | Высокое | Постоянная внутренняя коммуникация |
| Специалисты по транспортному планированию | Высокий | Высокое | Подключать к проверке требований и результатов |
| Сотрудники ручного подсчёта | Высокий | Среднее | Проводить интервью и UX-проверки |
| Коллеги из Сухуми | Средний | Среднее | Подключать как экспертов по необходимости |
| Специалисты по моделированию | Средний / высокий | Среднее | Согласовать структуру выходных данных |
| Проектировщики ОДД | Средний | Среднее | Уточнить требования к итоговым таблицам и картограммам |
| Лица, принимающие инфраструктурные решения | Средний | Среднее | Учитывать как конечных потребителей аналитики |
| Университет | Средний | Низкое / среднее | Использовать как техническую площадку при необходимости |

## Что важно согласовать со стейкхолдерами

- Какие классы транспорта нужны в первой версии.
- Какие направления движения обязательно распознавать.
- Какую ошибку подсчёта заказчик считает допустимой.
- Как сравнивать результат системы с ручным эталоном.
- Какой формат результата нужен в MVP: Excel, CSV, картограмма или несколько вариантов.
- Какие видео использовать для тестирования.
- Нужно ли учитывать пешеходов уже в первой версии.
- Какая скорость обработки считается достаточной.
- Где будет запускаться система и какие ограничения есть по вычислительным ресурсам.
- Как часто проводить встречи и показывать прогресс.
