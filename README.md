# InnovaTransport - traffic analysis

Репозиторий с материалами и рабочим сервисом автоматического анализа
транспортных потоков по видео.

Локальное приложение для автоматического подсчёта транспорта и пешеходов по видео. Пользовательская разметка линий остаётся доступной для подсчёта проездов через конкретный участок. Состояние хранится в SQLite, видео не отправляется во внешние сервисы. Интерфейс на русском языке.

## Запуск

Нужны Docker Compose и доступ в интернет для установки Python-пакетов. По умолчанию новые записи обрабатываются в **быстром режиме YOLO11s + ByteTrack**: 6 кадров/с по времени видео; видео декодируется полностью, но в модель передаются только выбранные кадры. Поэтому временные метки сохраняются, но короткие объекты между выбранными кадрами могут быть пропущены. Скачайте официальные веса YOLO11s, если их нет в `data/models/`:

```bash
python3 scripts/fetch_weights.py --model yolo11s.pt
```

Ансамбль YOLO11m + YOLOv10m с WBF остаётся доступен как отдельный, значительно более медленный режим. Для него выполните `python3 scripts/fetch_weights.py --ensemble`. На macOS при ошибке сертификата Python запускайте загрузчик из виртуального окружения после установки зависимостей: `.venv/bin/python scripts/fetch_weights.py --model yolo11s.pt`.

```bash
docker compose up --build
```

Откройте http://127.0.0.1:8000. Если весов нет, worker завершит задачу с понятным сообщением об ошибке; фиктивных результатов нет. Для подбора числа CPU-потоков worker установите `INNOVA_TORCH_THREADS` (по умолчанию 4) перед `docker compose up --build`. При ограничении CPU до 2 потоков целевые 30 минут могут быть недостижимы с частотой 6 кадров/с: worker автоматически уменьшает её по измеренной скорости, но это может ухудшить подсчёт.

Без Docker (Python 3.11 или 3.12, `ffmpeg`, зависимости ОС для OpenCV):

```bash
python3 -m venv .venv
.venv/bin/pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В другом терминале запустите `.venv/bin/python -m app.worker`. Данные хранятся в `data/`; можно изменить путь через `INNOVA_DATA`, но веса по умолчанию остаются в `data/models/` внутри проекта.

## Работа

1. Загрузите запись MP4/MOV/MKV/AVI/WebM и выберите её в левом столбце.
2. По умолчанию включены «Автоматически» и «Быстрый»: нажмите «Запустить анализ» без разметки. Частоту кадров быстрого режима можно изменить в интерфейсе от 2 до 12 кадров/с (по умолчанию 6): ниже — быстрее, но можно потерять короткие события. YOLO11s на выбранных по времени кадрах находит классы COCO `0/1/2/3/5/7` (пешеход, велосипед, легковой автомобиль, мотоцикл, автобус, грузовик); ByteTrack из `supervision` присваивает `tracker_id`. Слабые детекции могут участвовать в связывании трека, но объект учитывается только после проверки устойчивости: не менее трёх наблюдений, не менее 0,4 с, достаточное среднее качество и движение с порогом, зависящим от размера рамки. Это отсеивает большую часть статичных и случайных срабатываний. Альтернативный «Ансамбль» обрабатывает **каждый** кадр двумя YOLO с WBF перед ByteTrack, но требует намного больше времени. Автоматический режим считает **каждый уникальный устойчивый трек один раз за анализ**, а не число пересечений перекрёстка.
3. Если нужен подсчёт **проездов через зону**, выберите «По моей зоне», поставьте на видео именованные линии въезда и выезда (по две точки), при необходимости область интереса, сохраните зону и запустите анализ. Вместо клика можно ввести координаты в процентах. При изменении зоны анализ запускается повторно; предыдущие результаты сохраняются отдельно.
4. Worker декодирует кадры с нормализованными временными метками, проводит детекцию и сохраняет треки, события и рамки для просмотра вместе с видео. `app.ensemble.FastFrameProcessor` и `EnsembleFrameProcessor` возвращают `supervision.Detections` с `xyxy` (пиксели), `class_id` (COCO), `tracker_id` и `confidence`; некорректные и дублирующиеся рамки отбрасываются, а оставшиеся ограничиваются границами кадра. ID и координаты записываются в `data/runs/<run_id>/detections.jsonl`, крайние точки траекторий — в `tracks.json`. В автоматическом режиме учитываются только прошедшие проверку устойчивости треки; проезды в пользовательской зоне сначала имеют статус «Проверить» и не включаются в итог до подтверждения.
5. Выберите вид узла: трёхлучевой (треугольная схема) или пересекающийся (четыре луча). Для файлов с названиями из приложенных «Примеров 1–4» форма сопоставляется **по имени файла** с соответствующими схемами: Пример 4 — трёхлучевой, остальные — пересекающиеся; это не распознавание геометрии из видео. Для других видео автоматическая классификация подтверждается **только при наличии траекторий всех четырёх подходов**; если данных мало, выберите вид узла вручную. Это не требует повторного анализа. Картограмма строится из фактически отслеженных перемещений: при недостатке полного маршрута оценивает преобладающее направление в кадре, помечая такие маршруты отдельно. Лучи получают стабильные локальные номера по положению на схеме; без калибровки камеры они не обязаны совпадать с нумерацией на исходном плане перекрёстка. Неопределённые направления отдельно отмечены и на схеме не показываются. Сводка и таблица показывают учтённые события независимо от картограммы.
6. Исправляйте события, подтверждайте или отклоняйте их и добавляйте пропущенные объекты на текущем времени видео. Изменения имеют версии и журнал `revisions`. Сводка, диаграммы категорий и временных интервалов обновляются после нового анализа и правок. Скачайте Excel, CSV либо JSON. Excel начинается с оформленных листов `Отчёт` и `Подсчёты`: второй повторяет структуру «направление × категория» из приложенных примеров, а технические листы с событиями, интервалами, покрытием картограммы и журналом проверки остаются доступными дальше. В Excel/JSON отдельно включены оценка маршрутов картограммы и число объектов без определённого направления; 15-минутные интервалы имеют вид `[start,end)`. Пути к видео и весам сохраняются переносимо относительно `data/`, поэтому проект можно перемещать между локальным запуском и Docker. Если старый исходный файл пропал, интерфейс явно помечает его недоступным, сохраняет доступ к готовому отчёту и не предлагает ошибочный повторный запуск.

## API и Swagger

Интерактивный Swagger встроен в проект и доступен по адресу `http://127.0.0.1:8000/docs`; OpenAPI JSON — по адресу `/openapi.json`, проверка сервиса — `/api/health`. В Swagger показан компактный публичный API из 10 путей:

- `/api/videos/{video_id}/media` отдаёт видео или preview-кадр через параметр `kind`;
- `PATCH /api/runs/{run_id}` останавливает анализ или меняет тип перекрёстка;
- `/api/runs/{run_id}/results` объединяет сводку, события, картограмму и рамки объектов;
- `POST` и `PATCH /api/runs/{run_id}/events` добавляют и изменяют события.

Эталонный JSON/CSV/XLSX можно загрузить через `POST /api/videos/{id}/ground-truth` и оценить грубую матрицу с помощью `GET /api/runs/{id}/evaluate/{reference_id}`. Эти два диагностических маршрута не входят в основной Swagger. Для строк эталона нужны `from`, `to`, `category`, опционально `count`. Все архитектурные решения собраны в [`docs/adr/`](docs/adr/README.md).

Для выбора другой пары весов укажите в `POST /api/runs` `profile: "ensemble"`, `model` и `model_secondary` (оба файла должны находиться в `data/models/`). Например, `data/models/yolov8m.pt` + `data/models/yolov10m.pt`; оба файла можно получить через `python3 scripts/fetch_weights.py --ensemble --model yolov8m.pt`. Ранее созданные запуски с одним YOLO и ByteTrack/BoT-SORT продолжают обрабатываться прежним способом.

### Проверка скорости на приложенных видео

```bash
OMP_NUM_THREADS=2 .venv/bin/python scripts/benchmark_examples.py "Примеры подсчетов_автоматизация 2/Пример 1/Пример 1_утро_1.mp4" --seconds 30
OMP_NUM_THREADS=2 .venv/bin/python scripts/benchmark_examples.py "Примеры подсчетов_автоматизация 2/Пример 4/Пример 4_утро_1.mov" --start 300 --seconds 30
```

На тестовой машине (macOS, CPU, 2 потока) быстрый режим затратил 7,6 и 9,4 с на соответствующие 30-секундные фрагменты (по 180 кадров для модели). Фрагмент **900 с** из 916-секундного `Пример 1_утро_1.mp4` обработан за **228 с** (5400 кадров направлено в модель); 899,6 с из `Пример 4_утро_1.mov` — за **386 с**. В Docker при 4 CPU-потоках на 30-секундных фрагментах получены **46,8 с** и **49,3 с**, а полный проход worker по 125-секундному фрагменту занял **179 с**, создал 52 события и картограмму (32 маршрута определены, 20 — без направления). Это даёт ориентир **22–25 минут** на 15 минут видео; при 2 потоках 30-секундный фрагмент потребовал 110 с (ориентир **55 минут**). Это **экстраполяция**, полного 15-минутного запуска в Docker нет. При риске превысить 2× реальное время worker понижает частоту кадров после первых 30 секунд видео (минимум 2 кадра/с), что может ухудшить подсчёт. Скорость зависит от процессора и сцены.

Сверка с ручными таблицами показывает несопоставимость показателей без общей зоны учёта: «Пример 1 · утро · видео 1» — **316 автомобилей** за 900 с в автоматическом режиме против **217** по направлениям за всю запись; «Пример 4 · утро · видео 1» — **191** против **324**. Отдельная проверка YOLO11m на первом фрагменте дала **329 автомобилей** — замена небольшой модели на среднюю сама по себе не делает показатели сопоставимыми. Автоматика считает уникальные объекты во всём кадре, таблицы — проезды по именованным направлениям. Эти расхождения **нельзя** называть оценкой точности одной метрики; для сравнимой оценки нужна одинаковая зона/направления и проверка ID. В интерфейсе после 5% обработки показывается прогноз оставшегося времени; если worker не отвечает 5 минут, показывается явная ошибка вместо бесконечного «Идёт анализ».

## Границы метода

Точность зависит от ракурса, ночной видимости, окклюзии и качества детекции/трекинга; прореживание кадров ускоряет анализ, но может пропустить быстро проходящий объект, а ансамбль **не гарантирует** повышения точности без сравнения с эталоном. Если трекер присвоит одному объекту новый ID после потери, автоматический режим может учесть его снова; без пользовательских линий нельзя определить точное число проездов через конкретную границу. Направление по двум концам экранной траектории — **оценка**, а не географически точный маршрут. При боковом ракурсе камеры, закрытых подъездах или отсутствии трафика тип перекрёстка по одному видео установить достоверно нельзя: выберите схему по плану местности. Числа в приложенных Excel-файлах относятся к полным записям и нумерованным направлениям их схем; их нельзя напрямую сравнивать с 30-секундным тестом скорости без сопоставления нумерации и времени. Для старых анализов без `tracks.json` маршруты не восстанавливаются задним числом — повторите анализ. Эталонная функция считает ошибку матрицы, но не MOTA/IDF1.
